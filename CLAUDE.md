## SEO pipeline (generated output — never hand-edit)
Indexing is deliberate, not incidental: the signed acknowledgment states the
record is "indexed by search engines under my name to make it as findable as
possible." Treat discoverability as part of the record's integrity.
- **Workflow** `.github/workflows/publish-daily-seo.yml`. Fires on push to
  `photos/**` (the githubMirrorPhotos trigger), every 15 min on cron,
  `workflow_dispatch`, and `repository_dispatch: daily-packet-finalized`.
  Generated commits touch only the generated paths, and the push filter is
  `photos/**`, so runs never re-trigger themselves.
- **Required repo setting:** Settings > Actions > General > Workflow permissions
  = **Read and write**. The workflow's `contents: write` cannot exceed the repo
  default, so without this the commit step 403s on `git push`.
- **Publisher** `.github/seo-publisher/publish.mjs` (sharp, pinned in its
  package.json). Reads Weigh-ins (gid 1146060827; cols date/weight/note at 0-2,
  video at 7) and Attestation. A day publishes only when **finalized**: a video
  URL AND all four angle photos present in `photos/`, matched as
  `micheal-ray-berry-day-<NNN>-<angle>-<date>.<ext>`. Non-finalized days are
  skipped silently — that is why a Weigh-In Log row may render unlinked.
- **Generates, and commits ONLY:**
  - `daily/<date>-day-<NNN>/index.html` — permanent per-day page: canonical, OG,
    Twitter, JSON-LD (WebPage, Person, 4x ImageObject, VideoObject), prev/next.
  - `daily/<date>-day-<NNN>/index.html` for a MISSED day too, sourced from the
    AP Violation Log (gid 1365599185). Same URL scheme, so the archive and the
    prev/next chain have no gaps. §8 limits these pages to three facts: date,
    nature of the documentation failure, resolved/unresolved. NEVER publish
    consequence details. A documented day that also carries a violation shows
    both. Never infer a violation from missing photos — a §9 medical exception
    is an excused day, and only the AP's log distinguishes the two.
  - `daily/index.html` — archive hub linking every published day (CollectionPage
    + ItemList). `daily/published.json` — the list index.html reads to link its
    Weigh-In Log rows, so a row can never link to a page that does not exist.
  - `media/responsive/<yyyy>/<mm>/<dd>/*.webp` — 480/960/up-to-1600 variants.
  - `manifests/<date>.json` + `<date>.sha256` — per-photo SHA-256 evidence.
  - `sitemap.xml` (INDEX) + `sitemap-static|daily|images|videos.xml`.
- **Adding a site page:** put it in `STATIC_PAGES` in publish.mjs, not in the
  XML. Hand edits to any `sitemap*.xml` are overwritten on the next run.
- **Internal linking is the crawl path** and is load-bearing: index.html → the
  static `/daily/` link under the Weigh-In Log → hub → every day page, plus
  prev/next between days. All static HTML, no JS required. Do not remove that
  link — without it the day pages are reachable only by sitemap, the weakest
  discovery signal there is.
- **IndexNow** `submit-indexnow.mjs` submits only byte-changed URLs (pages are
  rewritten only when content actually changes), keyed by `indexnow-key.txt`.
  Reaches Bing/Yandex/Seznam/Naver. **Google does NOT use IndexNow** — Google
  discovery is sitemap + crawl only, on its own schedule.
- **Deploy:** the run POSTs `NETLIFY_BUILD_HOOK` when that secret is set, else
  relies on Netlify auto-deploy; then polls the newest page for up to 5 min and
  fails if it never becomes reachable. Script Properties already hold
  `NETLIFY_HOOK` (setNetlifyBuildHook) — same value, worth adding as the Actions
  secret so deploys fire immediately instead of waiting on polling.
- Video rich results realistically need YouTube-hosted videos; Drive-hosted
  entries still get correct VideoObject markup but Google cannot index them.

## Known gotchas (each cost a real bug)
- **Anchored status regex:** 'Unresolved' contains 'resolved'. Always
  `/^\s*(satisfied|resolved)/i` — never an unanchored test. This bug appeared
  THREE times (portal, violation mode, penalty log).
- **gviz sheet names:** a wrong `&sheet=Name` silently serves the FIRST tab.
  Site reads use gids for human-made tabs (Weigh-ins 1146060827, Penalty Log
  1365599185, Updates 742923954, Journal 482638063, Amendments 413137433);
  script-created tabs (Attestation, Health, Site State) are safe by name.
- **Sheet must be link-viewable** or every public CSV read comes back empty.
- **Google Health API:** weight/calories are rollup-only types — use
  `dataPoints:dailyRollUp` (weight.weightGramsAvg grams; total-calories kcal).
  Point filters 400 on these types. Steps etc. use the list endpoint. Weight
  autolog: manual rows before 2026-07-30, Health rows from that date.
- **Recording:** capture canvas 1080×1920 @9Mbps (2.5K stuttered); stills bump
  the camera to 4K and take a 3-shot sharpest-wins burst.
- **/exec URL is baked into site files** (ATTEST_ENDPOINT etc.) — changing the
  deployment id means rebuilding + committing the site. Prefer "New version" on
  the existing deployment.
- **sw.js caching:** bump `CACHE` version when shipping asset changes or phones
  keep the old tool.
- **`git add` on a missing path aborts the whole step** (exit 128,
  "pathspec did not match"). The publisher's commit step therefore loops the
  path list and stages only what exists — `daily/`, `media/` and `manifests/`
  do not exist until the first day is finalized. Do not collapse that loop back
  into a single `git add`.
- **Generated pages are byte-compared before writing.** Never add a timestamp,
  build id, or run number to generated output — it would make every run rewrite
  every page, spam IndexNow, and bury real changes in churn.
- Home Assistant bridge = environment/media/privileges ONLY. Never wire any
  device that restrains or confines a person; physical-safety devices stay a
  live human decision with manual release.
